基因组数据格式BED文件格式

2026-07-10
字数统计: 1.1k   |   阅读时长≈ 4 分钟

BED (Browser Extensible Data) 格式是一种广泛使用的、基于文本的基因组数据格式，用于定义和注释基因组上的特定区域。

它最初由UCSC基因组浏览器（UCSC Genome Browser）为可视化基因组注释而开发，如今已成为生物信息学领域的实际标准。

核心概念与字段

BED格式的核心是用坐标来定义基因组上的特征，如基因、调控元件或测序峰。一个BED文件由多行组成，每行代表一个基因组区域（feature）。其核心是3个强制字段：

  1. chrom: 染色体或序列的名称（例如 chr1, chrX, scaffold10671）。
  2. start: 区域起始位置，坐标从 0 开始计数。
  3. end: 区域结束位置，坐标从 1 开始计数，且该位置的碱基不包含在区域内。

关键规则：BED区域的长度 = end - start。例如，start=9, end=20 代表从第10到第20个碱基，长度为11。这种“左闭右开”的坐标体系是使用BED格式时最常见的错误来源。

相比于正常的1-based的闭区间，BED 的 start = 1-based位置 − 1，end 保持和 1-based 的 end 一致。

可选的扩展字段

在3个强制字段之后，还可以添加最多9个标准的可选字段，以提供更多信息。使用这些字段时必须按顺序，即如果使用了第N个字段，则它之前的所有字段也必须存在。

字段名 位置 描述
name 第4列 为该区域定义一个名称标签，用于在浏览器中显示。
score 第5列 一个0-1000的分数，用于在UCSC浏览器中表示灰度或颜色深浅。
strand 第6列 定义链的方向，用 +（正链）或 -（负链）表示。
thickStart 第7列 特征绘制为粗体的起始位置（例如基因显示中的起始密码子）。。
thickEnd 第8列 特征绘制为粗体的结束位置（例如基因显示中的终止密码子）。
itemRgb 第9列 用RGB值（如 255,0,0）为浏览器中的区域指定颜色。
blockCount 第10列 该区域包含的“块”（如外显子）的数量。
blockSizes 第11列 以逗号分隔的列表，表示每个块的大小。
blockStarts 第12列 以逗号分隔的列表，表示每个块的起始位置（相对于start字段的偏移）。列表项数应与 blockCount 对应。

其中，第7至第12列主要用于定义由多个外显子构成的复杂基因结构（即BED12格式）。如果存在 7 - 12 列，则第12列第一个块的起始值必须为 0，最后一个块的 起始位置 + 块大小 必须等于 chromEnd。块之间不能重叠。

重要规则与常见变体

  • 字段一致性：在一个BED文件中，所有行的列数必须相同。
  • 文件头部：文件可以包含以 browser 或 track 开头的注释行，为浏览器提供显示指引。
  • 常用变体：
    • BED3：仅包含3个强制字段。
    • BED4：包含3个强制字段 + name。
    • BED6：包含前6个标准字段（3个强制 + name, score, strand），这是最常用的格式之一。
    • BED12：包含全部12个字段。
    • BED3+ / BED6+：指在标准字段后，还可以添加任意数量的用户自定义列。

相关工具

BED格式的流行也催生了强大的分析工具生态：

  • BEDTools：一个功能强大的命令行工具套件，被誉为基因组区间分析的“瑞士军刀”。它可以高效地执行交集、并集、覆盖度计算、合并、补集等多种操作。
  • UCSC Genome Browser：BED格式的原始和主要应用平台，用于数据可视化。
  • bigBed：对于非常大的BED文件（通常超过50MB），可以转换为二进制的bigBed格式，以提高基因组浏览器的加载和显示效率。

总而言之，BED格式以其简单、灵活的特点，成为了存储和交换基因组区间信息的首选格式。
